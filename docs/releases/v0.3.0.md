# ShowPy v0.3.0: Phase 1, Priority 0

Audience: consumers that pin a ShowPy tag (host apps, agents, checkers) and maintainers of this
repository. Scope: what v0.3.0 changes against v0.2.0, how to migrate, the rulings behind the
changes, and what is still open.

Last updated: 2026-11-17

## Summary

v0.3.0 closes Phase 1 of the upgrade program. Every audited Priority 0 defect is fixed, and the
release adds text on the field, stage 1.

| Measure                            | Before Phase 1 (2026-11-13) | v0.3.0 (2026-11-17)          |
| ---------------------------------- | --------------------------- | ---------------------------- |
| Open ledger defects, default suite | 528                         | 373                          |
| Open ledger defects, `nox -s slow` | not recorded                | 1                            |
| Priority 0 items with an open test | 13                          | 0 (P0 #5 closed by decision) |
| Collision segment bound (0.02 m)   | exceeded by up to 1.0 m (1) | largest gap 0.019999 m (2)   |

(1) The audit's worst case: a 4-cycle `weave` custom motion compiled to one segment 1.0 m off
its path; in the audit's 150-spot mixed show, 83 of 4,350 plans broke the bound. (2) The 300
spots x 60 sets scenario test: 12 of its 60 transitions (every sixth, plus the two around the
inserted sub-set), every spot's segments, each checked at 9 probes.

The open counts are the `Ledger: N open` line the ledger plugin prints. 373 is net: lanes also
added ledger IDs for defects they found and did not fix (UP-9.7-94 among them).
`test_no_priority_zero_defect_remains` scans every test docstring that cites a Priority 0 item
(54 tests) and fails if any still carries a defect marker. P0 #5 (agents writing designer files
through public APIs) closed by the maintainer's decision of 2026-11-15: permissions belong to the
host.

Priority 0 items, numbered as in `docs/upgrade-plan.md` section 3:

- P0 #1: `renumber` plus save no longer deletes or reassigns set scripts.
- P0 #2: `InMemoryRepository` no longer loses updates under threads.
- P0 #3: tampered `next/`, tree and blob files fail closed as `CORRUPT`, and symlinks anywhere
  under a show folder are refused.
- P0 #4: every commit, from any caller, must decode into a valid `Show`.
- P0 #5: closed by decision; permissions belong to the host.
- P0 #6: the `PathEngine` guarantees its collision-segment bound.
- P0 #7 and #8: hangs and unbounded allocations end at named caps checked before allocating
  (`showpy.core.caps`).
- P0 #9: ordered tuples instead of frozensets, and RFC 8785 canonical hashing, make output
  hash-seed independent.
- P0 #10: join tokens, contact-free claims and CSV formula neutralizing.
- P0 #11: mirrored landmark fits are refused, and sheet replacement is removed.
- P0 #12: `place` and `apply_match` keep forms and placements consistent.
- P0 #13: every lock and pin bypass in `two_part`, the route builders, cast edits and `rebuild`
  is closed.

**New: text on the field, stage 1.** Spell text as an editable `text` form with an exact spot
count, or one derived from a spacing between spots:

- Five bundled single-line fonts: `relief-singleline`, `hershey-roman`, `hershey-script`,
  `hershey-greek` and `simplex`, with their licences. User fonts load as `showpy.font.v1` JSON
  through `register_font`. A font's identity is `asset:sha256:<hex>` of its bytes.
- `layout_text` handles per-character font fallback, `\n` line breaks, alignment, anchor,
  spacing and rotation. There is no shaping and no kerning.
- `text_form` spreads exactly `n` spots over the strokes in reading order. `edit(form, text=...)`
  keeps members and count. The count changes only through `edit_text_count`, which names the
  spots to add or remove. `text_spot_count` predicts a spacing-derived count up front.
- Spots keep a soft junction gap (0.25 of the smaller local stroke spacing) where strokes meet,
  and `text_report` lists every stroke that could not keep it.
- `export_json(..., font_registry=)` embeds the fonts of text forms, and `import_fonts` verifies
  and registers them.
- Caps: `MAX_LAYOUT_CHARS` 1,000, `MAX_TEXT_SPOTS` 10,000, `MAX_FONT_BYTES` 8 MiB, glyph,
  stroke and layout piece caps about 10 times the bundled maxima, and `MAX_LAYOUT_CURVE_PIECES`
  60,000. The worst legal text builds a text form in about 3 s (measured on the maintainer's
  WSL2 machine).
- Golden: GO TEAM n = 120, Équipe 2026! n = 200 and ΑΒΓ n = 45, with no crowded stroke.

**Also fixed.** `make_route` offset route members by the first vertex matching their start, so
members sharing a start got wrong offsets; it now offsets them by their place in the file. This
had failed the nightly property run since 2026-11-15.

**Gates and tooling:**

- A 300 spots x 60 sets scenario test (`tests/scenario/test_phase1_scenario.py`, slow) runs the
  whole edit, save, publish and revert cycle (see Verification).
- `test_no_priority_zero_defect_remains` fails if a Priority 0 test regains a defect marker.
- A guard fails if a library docstring or comment cites an ADR, a docs file or a ledger ID;
  code states the rule instead.
- `nox -s fuzz` fails when it collects no fuzz target, instead of passing on pytest's exit
  code 5.
- Refreshing the API snapshot from scratch (`SHOWPY_UPDATE_API=1` with no snapshot file) is
  refused once the changelog holds a released version, so a deleted snapshot cannot hide an
  unnamed API change.

## Breaking changes

Models and core:

- `FrozenModel` constructors, `model_validate` and `model_validate_json` raise `SchemaError`
  instead of `pydantic.ValidationError`.
- `FrozenModel` rejects NaN and infinity in every float field.
- Every `content_hash` value changes once. `content_hash` takes a keyword-only `domain` (default
  `showpy.content`), limited to `[a-z0-9_.]`.
- `Spot.tags` and `Cast.selections` are ordered tuples, not frozensets.
- New output-size caps (`MAX_POINTS`, `MAX_TABLE`, `MAX_GRID_CELLS`, `MAX_RANGE`, `MAX_DEPTH`,
  `MAX_TEXT_CHARS`, `MAX_IMAGE_PIXELS`, `MAX_VIDEO_PIXELS`) refuse inputs that ran
  unbounded or hung before.
- New: `FrozenModel.replace` (a revalidating `model_copy(update=)`), `require_finite`,
  `require_size`, `check_id`, `is_device_name`, `split_id`, `canonical_value` and `jcs`.

Cast and sheet:

- `add_spot`, `add_spots_along`, `fill_spots` and `duplicate_spots` gain keyword-only `force`.
  `delete_spots` takes `force` keyword-only, and `delete_spots(force=True)` drops pins on the
  spots it deletes.
- `split` raises `SchemaError` when `k` exceeds the selection size.
- `replace_sheet` and `SheetReplaceReport` are removed.
- `similarity_fit` refuses mirrored landmark fits (`REFLECTION`), plus degenerate, non-finite,
  mismatched and single-point input.

Choreography:

- `place` returns `(Set, list[Form])`.
- `two_part`, `rotate_path`, `follow`, `follow_and_set_targets` and `counter_march` take
  keyword-only `force` and raise `LockedError` on locked rows and pinned placements without it.

Show, storage and collaboration:

- `Revision` holds only `id`, `parent`, `at` and `changed`. Removed: `Revision.actor`,
  `Revision.message`, `Revision.kind`, `Revision.target`, `Principal`, `RevisionKind`,
  `CanvasEvent.actor` and `Workspace.principal`.
- `actor=` and `message=` are removed from `transaction`, `put_show`, `put_set`, `put_script`,
  `put_paths`, `put_forms`, `Workspace.commit`, `Workspace.write` and `save_show`.
  `transaction` and `Workspace.commit` also lose `kind` and `target`.
- `open_workspace` takes `(repo, show_id)`.
- `undo`, `redo` and `snapshot` are removed.
- Agent writes to designer files, pins and `show.json` are no longer refused; the host refuses
  them first.
- `apply_event` takes keyword-only `force: bool = False`. Without it, pinned items, an unpin
  event and a pin event that replaces an existing pin record raise `LockedError`.
- `Set` gains `Set.key`, written to `set.json` after a renumber; v0.2 readers refuse such a file.
  Repository paths address sets by key. `Workspace.commit` maps display-ID paths to key folders;
  an ambiguous folder raises `StorageError` `AMBIGUOUS_PATH`. `Repository.put_set` keeps the
  stored key of the set it replaces.
- `Repository` gains `Repository.documents(show_id, revision=None)`. `Workspace.tree_at` returns
  a read-only `Mapping` instead of a `dict`.
- Commits refuse derived tables (`/show/index.csv`, `*/placements.csv`) with `LockedError`
  `READ_ONLY` on both backends, and refuse a `set.json` whose `id` the show encoder refuses.
- A new show whose ID is a Windows device name (`con`, `nul`, `com1`, alone or before a dot)
  raises `StorageError` `BAD_PATH` on every platform.
- `put_forms` and a `FormOp` refuse a form ID that another set holds.

Export and publishing:

- `publish` takes keyword-only `join_token`, required on the first publish, and accepts only
  https `base_url` values without query, fragment or credentials. The publication stores only
  the token's SHA-256 (`Publication.join_token_sha256`); `Publication.link` carries no token.
- New: `join_link(pub, token)` and `verify_join_token(pub, token)`. `qr_code` takes the token:
  `qr_code(pub, token, size=512)`. `join_link` and `qr_code` refuse a stored link that is not
  https or has a query or fragment.
- `Claim` drops performer contacts on load and construction. `claim_spot`, `claims`,
  `who_is_on`, `notify_changes` and `performer_view` return contact-free performers.
- `to_csv` prefixes `'` to text cells that start with `=`, `+`, `-`, `@`, tab or carriage return
  and are not plain decimals. It takes keyword-only `neutralize`. `export_frames_csv`
  neutralizes its `entity` cells, `/show/index.csv` its `set` and `cue` cells and
  `placements.csv` every string cell, the same way.
- `import_positions` drops the stored paths of a transition it splits and raises `LockedError`
  on a locked one unless `force`.
- `export_video` raises on a degenerate canvas or an empty encoder output instead of returning
  `b""`.

`CHANGELOG.md`, generated by git-cliff, lists every change by commit under "Unreleased". It
lists the `content_hash` `domain`, the caps, `similarity_fit`, the route-builder `force`, the
device-name refusal and the commit refusals under features and fixes, not under "BREAKING
CHANGES". This page is the complete list.

## Migrating from v0.2

1. **Errors.** Catch `SchemaError` (or `ShowPyError`) where you caught `pydantic.ValidationError`.
   `SchemaError` is not a `ValueError`, so `except ValueError` no longer catches bad model data.
2. **NaN and infinity.** Documents holding `NaN` or `Infinity` no longer decode; they raise
   `SchemaError`. Repair them before upgrading.
3. **Hashes.** Every `content_hash` changes once. Stored revision IDs are kept. The first write
   after the upgrade lands one normalizing revision that rewrites non-canonical documents (for
   example `-0.0` becomes `0`), then the edit's own revision. Loading rewrites nothing.
4. **Host responsibilities.** Permissions, authorship, commit messages and undo live in the host.
   Keep who and why in your own records keyed by revision ID, refuse agent writes before calling
   ShowPy, and build undo on `revert(ws, revision_id, at)`.
5. **`place`.** Unpack `set_, forms = place(...)` and store the filled forms.
6. **Sheets.** `replace_sheet` is gone. To change sheet, make a new show.
7. **Contacts.** Keep performer contacts in the host's roster keyed by `Performer.id`.
8. **Join tokens.** Generate a token (`secrets.token_urlsafe(16)` or longer), pass it to the
   first `publish(..., join_token=)`, and keep it in the host. ShowPy stores only its hash.
   Build the link with `join_link(pub, token)` and the code with `qr_code(pub, token)`. A v0.2
   publication stores no hash, so nobody can join it until you republish it with a token.
9. **Tags and selections.** `Spot.tags` and `Cast.selections` are tuples. Compare with tuples;
   set methods are gone.
10. **Cast edits.** `split` raises when `k` exceeds the selection. Pass `force` to `delete_spots`
    by keyword. Pass `force=True` to the four cast additions, to `two_part` and to the route
    builders where you mean to edit locked rows or pinned placements.
11. **Set keys.** After a `renumber`, `set.json` holds a `key` that v0.2 readers refuse, so do not
    open a renumbered show with v0.2. Read sets by display ID through a `Workspace`; `Repository`
    paths use keys.
12. **Show IDs.** New shows cannot use a Windows device name as ID. Existing shows keep loading.
13. **Legacy set IDs.** Stored set IDs that fail the new ID rules (such as `con`, a trailing `.`,
    or over 64 characters) and v0.2 set IDs that differ only by case (`1a`, `1A`) load, edit and
    save. `renumber` refuses such a show, and a revert that re-creates a deleted legacy folder is
    refused. Such a show cannot be renumbered until Phase 2's migration renames those sets; no
    function renames a set. To renumber sooner, re-create each such set under a valid ID with
    `add_set(show, new_id, counts, after=old_id, placements=old_set.placements)` and then
    `remove_set(show, old_id)`; its forms, stored paths and set script do not carry over.
14. **Canvas events.** Pass `apply_event(..., force=True)` to replay unpin events or pin events
    that replace a pin, including a replay of `events_since`.
15. **Derived tables.** Do not commit `/show/index.csv` or `placements.csv`; ShowPy computes them.
    Deleting a stored copy is still allowed.
16. **Custom repositories.** A host's own `Repository` implementation must add `documents`.
    Code that mutated the result of `Workspace.tree_at` must copy it first.
17. **Save cost.** Measured on the maintainer's WSL2 machine at 300 spots x 60 sets, the first
    commit in a process takes about 0.5 s (cold decode cache, 479 ms measured); later commits
    take about 0.2 s (184 to 208 ms). A CLI that saves once per process sees the 0.5 s.
18. **Web hosts.** The joinable link carries the token in its query. Serve join pages with
    `Referrer-Policy: no-referrer`, and swap the token for a session on the first request.

## Rulings recorded in Phase 1

One line each, cited by ID. `R<n>` and `L-<x><n>` are the phase ledger's; `<lane> R<n>` and
`<task>-R<n>` are a lane ledger's; lane F's rulings carry no ID and are cited by task. Process
rulings (worktrees, dispatch order, history rewrites) are left out.

Core and models:

- R7: `CountsPerMinute` stays finite-only; positivity arrives with format v2 (Phase 2).
- R8: `require_finite` accepts numpy scalars.
- R9: cap values kept as approved. `MAX_POINTS` is about 14 times the points of the largest
  measured show and `MAX_RANGE` about 16 times 600 spots, not the planned 100 times.
- R10 and the maintainer's decision of 2026-11-17: an ID whose part before the first `.` is a
  Windows device name is refused, and new show IDs that are device names are refused on every
  platform.
- D-R1: tags and selections given as sets are natural-sorted, so stored order is hash-seed
  independent.
- D-R3, D-R7, D-R9: `natural_sort` is total on any text; `split_id` refuses a trailing digit run
  longer than `ID_MAX_LENGTH`; `split_id` strips digits instead of a backtracking regex.
- L-D1: `delete_spots` takes `force` keyword-only, like the other cast edits.
- D-R5: a forced addition into a pinned set comes out pinned.
- Lane D, task D3: an unforced `add_spot` whose entrance follows a pinned set writes an
  off-field placement flagged pinned there, as `pin` does, so deleting that spot later needs
  `force`.
- L-F1: `CoordinateSystem.precision` stays a plain float in the model and is refused at use;
  the model constraint waits for format v2.

Geometry and text:

- C-R1: geometry checks raise `GeometryError` and spacing checks `SpacingError`, both wrapping
  `require_finite`.
- C-R2: `to_polyline` counts points as it subdivides and stops at `MAX_POINTS`; the hint says to
  pass a larger `tol`.
- C-R5: `scatter` keeps `n >= 1`.
- C-R6: `scatter` checks a proven upper bound on its sample count before sampling, so a
  field-wide scatter with a gap under about 0.1 m is refused.
- T-C1: text slots keep a soft junction gap where they can; otherwise the least crowded spread
  (at least 1 µm) is used and reported.
- T-C2: per-stroke and curved-piece caps bound the worst legal text to seconds.

Sheets:

- F2: `similarity_fit` raises `GeometryError` (`NOT_FINITE`, `BAD_SHAPE`), keeps the RMS spread
  threshold of 1e-6 m on both point sets, and refuses `REFLECTION` only when the smaller singular
  value is above 1e-9 times the larger, so collinear fits still fit.
- F2: overflow raises `NOT_FINITE`; there is no coordinate magnitude cap.
- F3: `from_coords` results are checked finite.

Engine and paths:

- lane B R5: jittered probes are seeded per entity and transition from a stable digest, never
  `hash()`.
- B-C1, lane B R8: `counter_march`, `follow_and_set_targets`, `rotate_path` and `follow` refuse
  locked rows and pinned placements unless `force`.
- L-B1: a route referenced by a locked row is part of that row.
- L-B2: spec-taking builders such as `two_part` guard the spec they are given; the commit check
  re-checks the stored show.

Forms and matching:

- L-G1, L-G3: a set's forms are those stamped with the set and listed in `Set.forms` (all stamped
  forms when the list is empty). `apply_match` ignores stale forms; `rebuild` on one raises
  `STALE_FORM`; stale forms still round-trip through storage.
- L-G2: drift of gapped slot orders is ledgered for Phase 2's typed open slots.
- G-R4, G-R10: `place` compacts gapped orders instead of refusing them.
- G-R5: `place` sets `Set.forms` to the placed forms plus forms still used by pinned
  placements, and clears stale form references on unpinned placements.
- G-R7: `rebuild(force=True)` moves pinned members and keeps them pinned.
- G-R11: `rebuild` regenerates every member's facing, form and order, and keeps the path rows of
  members that did not move.
- G-R13: `match_ops.is_elsewhere` stays out of the top-level API.

Show and storage:

- lane A R1: on read paths a missing, truncated or directory-shaped object is `CORRUPT`; `IO`
  covers other OS errors.
- A2-R1: symlinks anywhere under a show folder, dangling ones included, are `CORRUPT` on read and
  write; a revision whose ID or parent does not match its link is `CORRUPT`.
- A2-R3: `log()` has no chain-length cap; each link file is visited once, so cost is linear.
- A3-R1: a path that only looks inside a known root (`..`, `.`, `//`, trailing `/`, backslash,
  NUL, no leading `/`) is `BAD_PATH`.
- A3-R2: each `DocumentRepository` keeps a bounded decode cache keyed by document digest.
- A3-R3: a show document the decoder never reads, or a missing required one, is refused at
  commit.
- A6-R1, A6-R3: keys defaulted from stored legacy IDs are not re-checked on load; a key new to
  the tree must pass `check_id`.
- A6-R4, X-R22: legacy set IDs and v0.2 case pairs load, edit and save, but cannot be renumbered.
- A7-R1, A7-R4: loading keeps stored values such as `-0.0`; the first write lands one
  normalizing revision.
- A11-R1: `put_forms` updates `Set.forms`; set and form pins rescope the forms they cover.
- A13-R1: commits validate structured non-show documents such as `/canvas/comments.json`.
- A14-R1: the CSV cell neutralizer lives in `showpy.core.csv_cells`, below show and export.
- L-A1: `DocumentRepository.put_*` and `transaction` guard validity, not pins; edit functions
  enforce pins.
- L-A5: the 300 ms commit target applies to the warm path; the cold first commit is Phase 3.
- L-A6: commits check `revision.id`, refuse files over `BLOB_MAX_BYTES` before writing, and
  open stored files without following symlinks.
- X-R11: a commit refuses a `set.json` whose `id` the encoder refuses.
- X-R12: `apply_event` needs `force` to unpin or to replace a pin.
- X-R13: loading a show reads show documents only, never `/renders` or `/exports` blobs.
- X-R15: v0.2 shows whose set IDs differ only by case load again.
- X-R17: `put_forms` and `FormOp` refuse a form ID another set holds.
- X-R18: a file-backend commit verifies an existing blob's digest before keeping it.
- X-R19: commits refuse derived tables with `READ_ONLY` on both backends.
- UP-9.7-45 (fix "match transition pin IDs by their canonical spelling"): pin events and
  `unpin` match transition pin IDs by their canonical spelling (`pin_key`), so `1->2` and `1→2`
  name one pin.

Export and publishing:

- lane E R2: `performer_view` builds the animation URL without the link's query.
- lane E R4: `Publication.join_token_sha256` is optional; `verify_join_token` returns `False`
  when it is missing.
- lane E R6: a cell is numeric, and left alone by `to_csv`, only when it fully matches a plain
  decimal literal; header cells are neutralized too.
- lane E R8: `qr_code` keeps error-correction level M for every link.
- lane E R12: every `Claim` constructor, load and `replace` drops contacts.
- Maintainer decision of 2026-11-16: the stored link holds no token; `join_link` builds the
  joinable link and fails closed.
- X-R10: `export_frames_csv` neutralizes its `entity` cells and `/show/index.csv` its `set`
  and `cue` cells.
- X-R16: `import_positions` drops transitions it splits and checks locks.
- X-R21: `join_link` re-checks that the stored link is https; `revert` restores pinned items
  without `force`, and the host decides whether to allow it.

## Known limitations and parked items

Storage and security (Phase 3 unless noted):

- Windows junctions report a directory to `lstat`, so the symlink refusal misses them.
- Tree records still use `os.replace`, which allows a rare race between two identical commits on
  Windows; an antivirus holding a temp file after the `next/` link can raise `IO` for a commit
  that landed.
- Deleting `next/` files rolls the head back silently; detecting it needs signed heads.
- Every repository call still rescans the revision log, so cost grows with history, and there is
  no total-bytes cap on a tree. The review measured 42,015 record reads and a 2.2 s load at 200
  commits before `Repository.documents` cut the per-path rescans.
- `revert` still reads render blobs when comparing trees.
- No directory `fsync`; a directory swap race needs an attacker who can already write the
  repository.
- Show IDs that differ only by case or a trailing dot alias each other on case-insensitive file
  systems (UP-9.7-14, UP-9.7-16).
- A commit that removes a cast spot still placed in a set lands (UP-9.7-94).
- `put_*` storage writes do not check pins or locks, by design (L-A1).
- The cold first commit costs about 0.5 s at 300 x 60 (maintainer's WSL2 machine) until
  per-document decoding lands.

Publishing:

- The library cannot measure token entropy, so a weak hand-picked join token passes; the digest
  is unsalted. The hint names `secrets.token_urlsafe(16)`.
- A host that passes a raw token as `join_token_sha256` sees it echoed in the `SchemaError`
  context.
- Token stripping on load does not decode an encoded `t` key (`%74`, `;t=`); only hand-built
  links have one.
- Claim edits ignore `Claim.locked`; authorization is the host's.
- `model_copy(update=)` and `model_construct` bypass the `Claim` validator and can keep a
  contact; the library never calls them on a `Claim`.
- ffmpeg probes untrusted audio without a pinned format or protocol whitelist, as in v0.2.
- `import_fonts` has no total byte budget beyond 64 fonts of at most 8 MiB.

Data model (Phase 2, format v2):

- Legacy set IDs that fail the ID rules, and v0.2 case pairs, cannot be renumbered until the
  migration renames them.
- Gapped slot orders compact on `place`, so a later `rebuild` may shift spots (L-G2).
- `CountsPerMinute` positivity and the `CoordinateSystem.precision` constraint.

Text on the field (stage 2 and later):

- `match`, `reorder`, `gate`, `split_form`, `merge_forms`, `place`, `rebuild`, `apply_match`,
  `swap` and `morph_targets` take no `font_registry`, so a user-font text form fails there with
  `MissingFontError`. `split_form` and `merge_forms` drop the text recipe.
- Repositories do not store fonts; a reopened user-font show needs the caller's registry and
  fails closed with `MissingFontError` without it.
- A curved stroke piece costs about 60 µs, hence `MAX_LAYOUT_CURVE_PIECES` 60,000.
- Dot-sized strokes (`.`, the dot of `i`) take 2 or 3 spots within centimeters. There is no
  minimum layout height, no Cyrillic font, no kerning, no shaping and no text along a curve.
- Curve lookup tables overflow with a raw `RuntimeWarning` past coordinates of about 1e154.

Code and tests:

- Twelve library modules pass 500 lines (not counting `__init__.py` and `_api_table.py`),
  among them `choreo/models.py` (738), `export/publish.py` (709), `geo/curves.py` (597),
  `choreo/forms.py` (569), `show/repositories.py` (546), `show/manage.py` (533) and
  `show/storage.py` (509); the splits are Phase 3 and Phase 6 work.
- Nine `test_regression_` tests were deleted with the features ADR 0003 and ADR 0017 removed.
  Inverted versions could keep those decisions under test; the maintainer has not ruled.
- Under the local `dev` Hypothesis profile, `test_fuzz_layout_text_piece_cap` can hit the
  200 ms deadline; the `ci` and `nightly` profiles gate.
- `nox -s slow` prints a 60 s faulthandler dump from `test_text_spread.py`; it is not a failure.
- `bounded_repr` cuts digits without a marker.
