# e8Show v0.4.0: Phase 2, foundations

Audience: developers and agent platforms that pin an `e8s` tag, and maintainers of this
repository. Scope: what v0.4.0 changes against v0.3.0, what it removes and what replaces it, how
to migrate code and stored shows, and what is still open. This page is the migration reference.

Last updated: 2026-11-23

## Read this first

- **The package is `e8s`.** The library was called ShowPy up to v0.3.0. The product is now
  e8Show and the package `e8s`: `import showpy` fails from v0.4.0, with no alias.
- **The licence changes.** v0.4.0 is licensed under PolyForm Noncommercial 1.0.0. v0.3.0 and
  every earlier release stay MIT.
- **This is the main breaking release before 1.0.** It needs Python 3.13, makes every boolean
  flag keyword-only, writes stored format v2, types every stored payload and validates models
  when they are built.
- **Removed names are gone, not deprecated.** The library has no users yet, so v0.4.0 deletes
  export, publishing, notes, landmarks, zones, coordinate wording, the stage template, sheet
  rendering, spot claimability and every alias in one step. Nothing warns. There is no
  `DeprecatedWarning` and no deprecation period. "Removed from the library" lists what replaces
  each and when.
- **v0.3.0 files still load.** Loading a v1 show migrates it in memory. Data that format v2 no
  longer holds is listed in `MigrationReport.dropped` with its stored value, and v1 notes move
  to a plain JSON document. Nothing is dropped silently.
- **Read "Migrating from v0.3" before upgrading**, and copy each repository before v0.4.0 first
  writes to it.

## Summary

v0.4.0 closes Phase 2 of the upgrade program. Every stored model is typed and checked when it is
built, the stored format has a version header and a migration chain, models have a small public
interface, and the library's scope narrows to space and time: positions, motion, timing and the
show model, with the checks, storage and migrations that serve them.

## The rename

<!-- fd4b7864 refactor!: rename the library to e8s; ADR 0020 and its addendum -->

| Before (v0.3.0)                  | v0.4.0                                               |
| -------------------------------- | ---------------------------------------------------- |
| distribution and import `showpy` | `e8s`                                                |
| ShowPy in prose                  | e8Show for the product; `e8s` for the package        |
| `ShowPyError`                    | `E8sError`                                           |
| `SHOWPY_UPDATE_API`              | `E8S_UPDATE_API`                                     |
| `SHOWPY_UPDATE_GOLDEN`           | `E8S_UPDATE_GOLDEN`                                  |
| `SHOWPY_UPDATE_MIGRATION`        | `E8S_UPDATE_MIGRATION`                               |
| `SHOWPY_UPDATE_SCHEMA`           | `E8S_UPDATE_SCHEMA`                                  |
| GitHub `abj360/ShowPy`           | `abj360/e8s`; GitHub redirects the old address       |
| format value (never released)    | `"format": "e8.show"`; schema file `e8.show.v2.json` |

- **No alias.** `import showpy` raises `ModuleNotFoundError`. Every public name whose signature
  printed the package path changes with it; the names themselves do not.
- **Frozen stored strings keep the old name**, in this release and every later one:
  - `showpy-hash/1`, the prefix of every content hash and revision ID;
  - `$showpy:map` and its `$showpy:` prefix, in the canonical bytes of maps with non-text keys;
  - `"format": "showpy.font.v1"`, inside every font file;
  - `showpy.show.v1`, the v1 schema file `showpy.show.v1.json` and its `"schema"` tag, which
    import still reads;
  - `showpy.revision` and `showpy.content`, the hash domains every revision ID and content hash
    is computed under.

  Stored revision IDs, content hashes and the five bundled font URIs do not change.

- **History is not rewritten.** In ADRs 0001 to 0019, the v0.3.0 notes and older changelog
  entries, `showpy` and ShowPy name the package now called `e8s`.

## Breaking changes

`CHANGELOG.md` is generated from commit messages at release time. This page is the complete
list. Each item names its commit in the page source. Names removed outright are listed in
"Removed from the library".

### Python, packaging and extras

- Python 3.12 is no longer supported: `requires-python = ">=3.13"`. CI runs 3.13 and 3.14 on
  Linux, macOS and Windows. <!-- a3c10ce4 build!; ADR 0011 -->
- A plain install pulls numpy, scipy, shapely, pydantic and pydantic-core only. pandas moves to
  the `tables` extra; `all` installs the same. Pillow, segno and imageio-ffmpeg are no longer
  dependencies: the code that used them is removed. <!-- 9769cfc8 build!; 98d8aad8; ad61195c -->
- Without `tables`, `Set.table`, `paths_table`, `speeds`, `energy_curve` and `phrase_profile`
  raise the new `MissingExtraError` (code `MISSING_EXTRA`) when called, never at import. Its hint
  is the install command. `import e8s.choreo.models` imports no optional dependency.
  <!-- 9769cfc8 -->

### Errors and validation

- `E8sError` replaces `ShowPyError` (see "The rename"). <!-- fd4b7864 -->
- `ValidationError` is renamed `ShowValidationError`; code `VALIDATION` is unchanged. The old
  name is gone. <!-- b0b0e292 feat(core)!; 354411f6 refactor!: remove every deprecated alias -->
- Every `E8sError` subclass takes `code: ErrorCode | None`. `ErrorCode` is a closed catalogue of
  86 codes (`docs/error-codes.md`). Error context is bounded on construction: text and reprs are
  cut to 80 characters around a `…`; lists, tuples and sets keep 20 items plus a `(+n more)`
  count and become lists; numpy values become plain numbers; other values become their repr.
  <!-- 9976d1c4 -->
- `ValidationIssue.code` is an `ErrorCode`; a code outside the catalogue raises `SchemaError`.
  <!-- 67f5ad18 -->
- `ValidationIssue.context` is a read-only `JsonObject`: nested lists read back as tuples and
  nested objects as `ReadOnlyMap`. `ReadOnlyMap` is hashable. <!-- 37c919cc -->
- `ValidationReport.to_json()` returns a JSON-safe dict, like every other model, instead of JSON
  text. Call `json.dumps(report.to_json())` for text. <!-- 8c3a01c2 feat(core)! -->
- `ErrorCode.FACING_RANGE` is gone; every model-valid facing is wrapped or refused, so it was
  unreachable. <!-- dcfeb671 -->
- `DeprecatedWarning` is removed. <!-- c96e67d7 refactor!: delete the deprecation machinery -->

### Flags and signatures

- **Every boolean flag is keyword-only**, with no positional fallback. A positional call raises
  `TypeError`; mypy and pyright report it before it runs. See "Keyword-only flags".
  <!-- 9de6243d refactor!; ADR 0009 decisions 1 and 2 -->
- `approx_equal` takes its tolerance as keyword-only `abs_tol` (was `tol`), and `round_to` names
  its second parameter `step` (was `precision`). The old names are gone. `approx_equal` refuses a
  negative or NaN tolerance. <!-- c398204a; aa0d5920; 07d617f4; 354411f6 -->

### Core types, IDs and bounds

- **ID aliases are `NewType`s.** Typed callers holding plain `str` wrap them (`SpotId("T1")`) to
  build models or index model mappings; public functions still accept `str`. <!-- a8600071 -->
- **`TransitionId` is a `NamedTuple`.** `parse_tid`, `transitions` and `transition_at_count`
  return it (repr `TransitionId(from_set='1', to_set='2')`); `parse_tid` refuses parts that fail
  `check_id`; `make_tid` is new; `TransitionId` is exported from `e8s`. <!-- 8bd85575; 7bdab24f -->
- `parse_ref` and `format_ref` refuse a reference whose id or version fails `check_sheet_id`
  (`..`, `/`, a leading or trailing `-` or `.`, `all`, a Windows device name, over 64
  characters, non-ASCII after NFC) and return the NFC-normalized id; `format_tid` refuses a
  tuple that is not a pair. <!-- 7b3b1471 -->
- `RESERVED_IDS` holds `props`, so `check_id`, `check_sheet_id` and every checked ID field
  refuse `props` in any case. <!-- 66d87acf feat(core)! -->
- `Set` refuses an ID that fails `check_id` when it has no explicit key; `Show` refuses set keys
  that repeat ignoring case, and form keys that fail `check_id` (such as `f-1`). Stored v1 IDs
  are renamed by the migration instead (see "ID renames"). <!-- c7bdf394; e82e2b69 -->
- **Stored bounds.** A stored value past `MAX_COORD_M` (1e6 m) or `MAX_COUNTS` (1,000,000), or a
  `CountsPerMinute` below `MIN_TEMPO` (1e-3), raises `SchemaError` instead of producing NaN or
  infinity later. `Point`, `Point3` and `Ring` items are `Meters`. <!-- 9a9393ac -->
- **Core helpers are total and exact.** `UnitRegistry` stores exact `Fraction` sizes in a
  read-only map; `normalize_angle` raises on NaN and infinity; `as_points`, `chunk_counts`,
  `round_to` and `register_unit` raise on inputs they used to accept; `Region` and
  `CountsPerMinute` reject invalid values. <!-- aa0d5920 -->
- **`Selection` is a value.** It is no longer iterable by ID (use `Selection.ids`); two
  selections with equal IDs compare equal whatever their description. <!-- fe9f3bc4 -->
- **Size caps.** `Cast` refuses more than `MAX_SPOTS` (5,000) spots and `Show` more than
  `MAX_SETS` (1,000) sets. See "Caps and limits". <!-- 01f8430e feat(core)! -->

### Selection grammar

- `select` refuses an expression that mixes `&` with `+` or `-` at one parenthesis level
  (`SchemaError`, code `MIXED_OPERATORS`); the hint shows both parenthesized readings. `&` may
  still chain with itself, and `+` and `-` combine left to right. Stored v1 selectors are
  rewritten with the parentheses that keep their v1 meaning. <!-- c9449a83; 719a7c74; ADR 0008 -->
- `define_selection` takes keyword-only `replace` and no longer overwrites silently: an existing
  name raises `SchemaError` (code `NAME_TAKEN`) unless `replace=True`. <!-- 751b4a29 -->

### Geometry

- Curves refuse inconsistent or non-finite construction: `CompositeCurve`, `TrimmedCurve`,
  `SvgCurve`, `BezierCurve`, `arc`, `circle`, `ellipse`, `rect`, `wedge`, `regular_polygon` and
  `star` raise `GeometryError`. <!-- c28fd1a6 -->
- `CompositeCurve` refuses parts that do not meet end to start. <!-- e5803353 -->
- **Set handling leaves `e8s.geo`.** The geo transforms (`shift`, `move_to`, `rotate`, `scale`,
  `expand`, `contract`, `set_interval`, `mirror`, `skew`, `affine`, `snap`, `align`,
  `distribute`) take points or a curve only and lose their `sel` and `force` parameters; given
  anything else they raise `SchemaError` ("`obj` must be points or a curve"). The versions that
  take a `Set` live in `e8s.choreo.set_transforms`, `set_snapping`, `set_measure` and
  `set_analysis`, and the top-level `e8s` names point at them. `symmetrize`, `snap_to_guides`,
  `on_field_ids`, `neighbors`, `nearest` and `symmetry_error` live only in `e8s.choreo`, and
  `e8s.geo.analysis` is gone. <!-- eb0ac25b refactor(geo)!; 354411f6 -->

### Time

- `Timeline` and `TempoSection` raise `SchemaError` for invalid timelines that v0.3.0 accepted;
  the clock also raises `HOLD_OVERLAP`. <!-- e6a941b2 -->
- `MeasureSetting` refuses lengths of 0 or less, negative change counts, and unsorted or
  repeated change counts. <!-- 497d6117 -->

### Cast

- Cast models are validated and frozen. `Group.limits`, `Cast.groups`, `Cast.selections` and
  `LabelScheme.prefixes` are read-only mappings; `Group` and `Spot` colors must be `#rrggbb`;
  `Group.default_radius` must be positive and finite; `LabelScheme.pad` is 0 to 8; `Cast` refuses
  selections naming absent spots and prefixes naming absent groups; `Spot.id` is checked.
  <!-- 6e60a0df -->
- `edit_group` is typed by the new `GroupPatch`. <!-- c0817e14 -->
- `rename_entities` is replaced by `rename_spots`, which returns a `RewriteReport`.
  <!-- 92e1dd1d; 354411f6 -->

### Sheet

- `Sheet` and `GuideLine` raise at construction for invalid data. `Sheet` loses `landmarks`,
  `zones` and `default_coordinates`. <!-- 91859387; ad61195c refactor!: remove landmarks, zones -->

### Forms

- **`Form.recipe` replaces `Form.kind` and `Form.geometry`.** `Form` takes `recipe`, a typed,
  versioned union tagged by `kind` (`LineRecipe`, `ArcRecipe`, `CurveRecipe`, `CircleRecipe`,
  `BlockRecipe`, `WedgeRecipe`, `PolylineRecipe`, `SvgRecipe`, `FillRecipe`, `ScatterRecipe`,
  `CustomRecipe`, `GeneratedRecipe`, `TextRecipe`; bases `RecipeBase`, `CurveRecipeBase`).
  `Form.kind` is derived from `recipe.kind`; `Form.geometry` is gone. `TextRecipe` gains `kind`,
  `recipe_version`, `n` and `transform`. `edit_params` reads and writes `recipe.params`. Every
  recipe's `transform` applies to its slots, and `transform_form` composes onto a stored
  transform. <!-- 43e883b5 (rebased de483f9; its empty-SVG footer claim is withdrawn); 354411f6 -->
- **Open slots are `None` members.** `Form.members` is `tuple[SpotId | None, ...]`; read
  `Form.spots` for the spots alone. `custom_form` accepts `None` members; `filled_forms` and
  `place` return forms with `None` at each open slot, so `place` and `rebuild` keep spots on
  their slots. <!-- 9eeaa9b1 -->
- **SVG forms store each subpath as its own curve.** `SvgRecipe.curve` is now
  `SvgRecipe.curves`. Splitting an svg form gives custom forms. Count and interval spacing over
  several subpaths lay out exactly as in v0.3.0. <!-- 1c3a9381 (rebased 9df33aa); its
  SpacingError footer claim is withdrawn by 1b5c6c9a -->
- **Models moved.** The form, path and match models live in `e8s.choreo.form_models`,
  `e8s.choreo.path_models` and `e8s.choreo.match_models`; `e8s.choreo.models` keeps `Placement`,
  `PlacementPatch`, `Set` and `SpotCount`. The top-level names do not change.
  <!-- dd4122c1; 354411f6 -->
- `Form.meta` is a read-only `Mapping[str, str]`, not a `dict`, so forms hash. <!-- a466e03b -->
- `FormFnRegistry.fns` is a read-only mapping. `spiral_points`, `sine_wave_points` and
  `rose_points` raise `SchemaError` for unknown or invalid parameters (new `SpiralFormParams`,
  `SineWaveFormParams`, `RoseFormParams`); `register_form_fn` refuses a generator whose probe
  raises. <!-- 355ec7ec -->
- `split_form` without `ids=` names its parts `<id>_1` and `<id>_2`, not `<id>-1` and `<id>-2`.
  <!-- 64fe3298 -->
- `SpacingSpec` refuses a negative extra gap in `gaps`. <!-- 05c195cb -->
- `Placement` wraps `facing`, and `FacingSpec` wraps a fixed `value`, into [0, 360).
  <!-- daa4ecf9 -->
- `Set.with_placements` takes `Placement | PlacementPatch` values (new `PlacementPatch`) and
  refuses a plain dict. <!-- 4539bc70 -->

### Paths and the engine

- **Typed motion parameters.** `PathRow.motion_params` holds `WeaveParams`, `ZigzagParams`,
  `FigureEightParams` or `SpiralParams` for the built-in motions and a read-only JSON object for
  others; built-in parameters refuse unknown keys. `register_motion`, `MotionRegistry` and
  `MotionRegistry.with_motion` refuse to rebind `weave`, `zigzag`, `figure_eight` or `spiral`
  (code `RESERVED_MOTION`). `weave`, `zigzag`, `figure_eight` and `spiral_motion` take
  `Mapping[str, JsonValue]`. New: `BuiltInMotionParams`, `MAX_MOTION_CYCLES` (100),
  `MAX_SPIRAL_TURNS` (20). <!-- 69cd1c8f -->
- **Typed route curves.** `Route.curve` holds an `AnyCurve`, not a recipe dict;
  `TransitionSpec.rows` and `TransitionSpec.routes` are read-only mappings; a route stored under
  a key other than its ID is refused. <!-- 2795209d -->
- **Typed facing values.** `PathRow.facing_value`, `FacingOverride.value` and
  `MotionPlan.facing_value` hold `FixedFacing`, `PointFacing` or `EntityFacing` (or `None`), and
  the kind must match `FacingMode`. New: `FacingValue`. <!-- bf5e78b3 -->
- **Typed fix parameters.** `Fix.params` holds `DelayFix`, `BendFix`, `StaggerFix` or
  `ReassignFix` (union `FixParams`). <!-- 3c4a554f -->
- `Easing` refuses a strength below 1 and a steps easing over `MAX_EASING_STEPS` (200).
  <!-- 2eb555db -->
- `PathRow` rejects a non-finite `start`; `TransitionSpec` rejects negative `counts`;
  `min_gaps`, `closest_approach` and `energy_curve` raise `PathError` for inputs that used to
  leak. <!-- f31989a4 -->
- **Aliasing motions are refused.** A motion whose midpoints stray from its compiled polyline by
  more than `motion_tol` raises `PathError` `SEGMENT_BOUND` at compile time: weaves near
  `MAX_MOTION_CYCLES`, zigzags whose corners fall between samples, long spirals. `PathEngine`
  takes keyword-only `motion_tol` (default 0.02 m). A custom `MotionFn` receives 513 shares per
  compile, not 257. <!-- 3d1f3911 (no `!`; behaviour change named by lane B for these notes) -->
- **Platform-stable discrete output.** `min_gaps` names each pair (`GapInfo.a`, `GapInfo.b`) in
  natural spot ID order (`T2`, `T10`, where it returned `T10`, `T2`), and orders pairs whose gaps
  agree to 9 decimals, and picks its `top` pairs, by those names. `segments` and
  `entity_segments` no longer return a sliver segment for a motion break within 1e-9 m or counts
  of a window end. `make_route` and `counter_march` store route offsets equal to the route
  curve's own arc lengths, which may differ from v0.3.0 in the last bit. Segment counts and gap
  orders can change once. <!-- de9da6ac; e89ac264; 2358f714; 5e43fbb2; 157c51da -->

### Matching

- `MatchOptions.weights` takes `MatchWeights`, not a free dict; `MatchOptions` refuses a
  negative `no_backward` and a bool slot index; a non-finite or negative weight or `True` as a
  slot raises `SchemaError`. <!-- ddd4fa3f -->

### Show and storage

- `Show.forms` and `Show.dependencies` are read-only mappings; `ShowLookup` and `Show.lookup`
  are new (a cached index). <!-- 6b689394 -->
- `Show` has no `notes`, `coordinates` or `zones` field, and gains `extensions` (see "Extension
  keys"). `Spot` has no `claimable` field. <!-- a8ca36b2 feat(show)!; ad61195c; bd41b9c1;
  26536fac -->
- `CanvasEvent.payload` is a typed model, not a dict. Build events from payload models or decode
  stored JSON with `decode_event`. New payload model `Highlight`; `Anchor` is public at
  `e8s.show.models.Anchor`. v0.2 events that carry `actor` decode with the actor dropped and
  reported. <!-- 450f842e; 03908b87 -->
- `save_show`, `load_show` and every repository write store `show.json` with the format header
  first, so the first save of a v1 show writes one revision, which a v0.3.0 reader refuses.
  Commits and workspace writes refuse a `show.json` without the current header (`SchemaError`
  `OLD_FORMAT`). <!-- 8925ffc8; d7710104 -->
- Loading a v1 show renames its invalid and case-pair IDs, and the first save stores the new IDs
  and set folders; a v2 tree holding a v1 ID is refused. <!-- e0f0ce4f feat(show)! -->
- `validate_show` reports `BAD_ID` for a form ID with an inner `-`. <!-- 00d77681 -->
- `add_set` refuses two placements for one spot; it kept the last one silently.
  <!-- 98d38634 (no `!`) -->

### Interchange

- `export_json` writes `{"format": "e8.show", "version": 2, "show": {...}}`, plus `"fonts"` when
  text forms need them and the show's `x-` keys, instead of `{"schema": "showpy.show.v1", ...}`.
  `include` takes one field name or an iterable. It takes no `notes` or `extensions` keyword.
  <!-- 8925ffc8; 16add267; 9d4e7400; 5cea7fdb -->
- `import_json` refuses non-strict JSON (lone surrogates, NaN, duplicate keys, a byte-order mark,
  nesting past 100 levels) and a v1 tag beside a format header (`UNKNOWN_FORMAT`).
  <!-- 8925ffc8; cdc7c32b; b9249afb -->
- `import_json` raises `SchemaError` for a top-level key other than `schema`, `format`,
  `version`, `show`, `fonts` or a key starting `x-`. <!-- 6eed120d fix(show)! -->
- A v0.3.0 export of an unsaved show holding a transition between non-consecutive sets fails
  closed on import with `SchemaError`; v0.3.0 dropped that transition's data.
  <!-- f1b0c6c0; 045af390 (no `!`; the L0.9 ledger asked for this line) -->
- `import_positions` rejects an entity ID that is not a valid spot ID (`SchemaError` naming the
  line) and stores `facing` wrapped into [0, 360). <!-- 16add267 fix(export)! -->
- `export_json`, `import_json`, `import_fonts` and `import_positions` are defined in
  `e8s.show.interchange`; their `e8s.export.data` and `e8s.export.positions` paths are gone. The
  top-level names do not change. <!-- 3f4a9dda; dd231e77; 98d8aad8 -->

## Format v2 and the v1 read window

<!-- 8925ffc8 (format header and chain); 4f586380; cdc7c32b; ADRs 0007 and 0023 with their
addenda -->

**One header, in `show.json`.** v0.4.0 writes `"format": "e8.show"` and `"version": 2` as the
first two keys of `/show/show.json` and of the `export_json` document. Other documents in a tree
carry no header; the tree's `show.json` versions them all. The notes document carries its own
(see "Notes document").

**What v0.4.0 reads.**

| Stored form                                                   | Read as                                  |
| ------------------------------------------------------------- | ---------------------------------------- |
| A tree whose `show.json` has no header                        | v1, migrated in memory                   |
| An `export_json` document tagged `"schema": "showpy.show.v1"` | v1, migrated in memory                   |
| `"format": "e8.show"`, `"version": 2`                         | v2                                       |
| A newer version                                               | refused, `VersionError` (code `VERSION`) |
| Any other `format`                                            | refused, `SchemaError`                   |

**The v1 read window.** Every release before 2.0.0 reads v1, and at least until 2027-11-18,
whichever is later. The notes of a v1 show keep reaching the host as plain JSON for the whole
window, through a private reader. Removing the v1 reader is a major-version change with a
release-notes entry. The library never writes v1 again.

**Planned versions.** v0.5.0 and v0.6.0 keep writing v2. v3 ships at v0.7.0 with the sheet,
marking and floor shapes. At most one format version per release. A v0.4.0 reader refuses v3
with `VersionError`.

**Strict JSON.** Every stored and imported document is parsed strictly: `NaN`, `Infinity` and
`-Infinity` tokens, duplicate object keys, a byte-order mark, lone surrogates, nesting deeper
than 100 levels (`MAX_NESTING`) and integers longer than 640 digits are refused with
`SchemaError` code `STRICT_JSON`, naming the document and the token or key.
<!-- cdc7c32b; b9249afb; 555a1e9a; 5c3ebe22 (fonts); 233323a6, fa5fdcc1 (workspace and tree
records) -->

**Nothing is rewritten on read.** Loading migrates in memory. The first save after the upgrade
writes the v2 documents, and the notes document if the show had notes, in one revision; a second
save writes nothing. Revision IDs already stored never change. A v0.3.0 reader refuses v2 with
`SchemaError`, so it fails closed.

**What the v1-to-v2 migration changes**, in order (`e8s/show/migrations/`). Eight sub-steps
work on the stored JSON, then `ids` on the show, then `notes` beside it:

1. `forms`: `kind` and `geometry` become a typed `recipe` with its defaults written out; gapped
   slot orders become open slots (`None` members); a v1 svg `curve` becomes `curves`. A geometry
   v2 cannot hold (an arc of zero sweep, for example) is refused with `SchemaError` naming the
   document, field and value. <!-- 43e883b5; cb58cd87; a58b323e -->
2. `paths`: `motion_params` become typed parameters, dropping keys the built-in motion never
   read; easing strengths below 1 become 1; `Route.curve` becomes a typed curve; bare facing
   values become tagged ones.
3. `selectors`: stored selector text gets spaces around glued operators and the parentheses
   that keep its v1 left-to-right meaning (`A + B & C` is stored as `(A + B) & C`). No stored
   show changes which spots it selects. <!-- 719a7c74 -->
4. `timeline`: tempo sections, holds and measure changes are sorted by count; ramps without a
   target or length become steady; duplicate measure changes keep the longest. Two tempo
   sections or two holds at one count are refused. <!-- f6db9f1a; 1ba2507b; 9437760e -->
5. `facings`: stored placement and fixed form facings are wrapped into [0, 360).
6. `sheet`: the sheet's `landmarks`, `zones` and `default_coordinates` and the show's
   `coordinates` and `zones` are dropped and listed in `MigrationReport.dropped`. <!-- ad61195c -->
7. `cast`: `claimable` is dropped from every spot and listed when it was not the v1 default
   `performer`; a group stored under another key takes its own key; dangling selection IDs and
   label prefixes are dropped. <!-- bd41b9c1 -->
8. `events`: v0.2 events that carry `actor` decode with it dropped and reported.
9. `ids`: IDs that fail the ID rules are renamed once, by rule (below). <!-- e0f0ce4f -->
10. `notes`: notes move out of the show to `/notes/notes.json`, with their IDs and anchors
    renamed through the same renames. <!-- a8ca36b2; 2faf98f6 -->

Constraints v1 could hold and v2 refuses are refused at migration, never repaired by guessing: a
tempo of 0 or less, a negative show length, a measure length of 0 or less, a dict key that
differs from the contained ID. None of them could be written by a v0.3.0 edit function.

**Reports.** `migrate_documents(docs)` returns the migrated documents and a `MigrationReport`;
`migrate_json(d)` returns `(show, report, notes)` for an interchange document. The report holds
`from_version`, `renamed` (per ID kind, in show order), `repairs` and `dropped` (one
`DroppedFields` per stored object that lost fields, with `document`, `location`, `stored_id`
and the stored `fields`). Dropped values are kept as stored: selector text in v1 grammar and IDs
before any rename. Also new: `read_version`, `FORMAT`, `CURRENT_VERSION`. Repository loads do not
return the report in this release. <!-- d476ff46 feat: add `migrate_json`; bd41b9c1; 1923e4c4 -->

**Expect `dropped` on most v0.3.0 shows.** A v0.3.0 show on a built-in field stores the field's
landmarks and coordinate systems, so its report lists them. The reviewed
fixtures in `tests/fixtures/repos/` show the shape: the v0.1.1 report lists one sheet landmark
and zone; the v0.2.0 and v0.3.0 reports list the 71 field landmarks and the coordinate systems,
and v0.3.0 also its selector zone.

### ID renames

<!-- e0f0ce4f; 705d29ea; 66d87acf; ADR 0007 addendum 2026-11-22 -->

Each stored ID that fails its ID check, or repeats ignoring case an ID of its kind kept earlier
in show order, is renamed once:

- NFC first; every character outside `[A-Za-z0-9_.]` (`-`, a space, `*`, a non-ASCII letter)
  becomes `_`, and each `..` run becomes `.`. Guide IDs keep an inner `-`; an edge `-` becomes
  `_`.
- Leading and trailing `.` are stripped; the ID is cut to 60 characters; an empty result
  becomes `id`.
- A reserved word (`all`, `props`, a Windows device name, ignoring case) gets a trailing `_`:
  `con` becomes `con_`, `Props` becomes `Props_`. A device name before an extension gets it
  before the dot: `con.5` becomes `con_.5`.
- A name still taken gets the smallest free suffix `.2`, `.3`, ... Valid IDs keep their spelling
  and pick first, and the first of a case pair is kept: `1a`, `1A` become `1a`, `1A.2`; `a-b`
  beside `a_b` becomes `a_b.2`.
- It applies to spot, set, form, route, guide, selection-name and note IDs. Show IDs are not
  renamed. Route IDs are unique per transition and guide IDs per sheet.
- Every reference follows: selections, forms, paths, pins, cues, canvas comments and selection,
  note anchors. A set's key follows its ID unless the key was written explicitly, and files under
  `/sets/<old>/` read at `/sets/<new>/` before the first save and move there in its revision. A
  stored selector that names spots by label (`T*`, `T1-T8`) is stored as its ID list when spots
  are renamed, and recorded as a repair.

After migration, `renumber` works on every show, including the v0.3.0 shows with legacy set IDs
or case pairs it refused.

## Model interface

<!-- 8c3a01c2 feat(core)!: add `FrozenModel.to_json` and `FrozenModel.from_json`; df7dc43a;
69c36377; db630080; 1e2ee4cb; ADR 0026 -->

Every e8s data class is a frozen model. Callers may rely on exactly this:

- attribute reads of the documented fields and properties;
- `==` and `hash()`; equality compares field values, never cached arrays;
- `replace(**changes)`, which returns a revalidated copy;
- `to_json()`, which returns a JSON-safe dict, the shape stored documents hold;
- `Model.from_json(data)`, which validates parsed JSON into the model and raises `SchemaError`
  on bad data; `data` may be any parsed JSON value.

pydantic's own methods are not the interface: `model_validate`, `model_validate_json`,
`model_validate_strings`, `model_dump`, `model_dump_json`, `model_copy`, `model_fields`,
`model_construct` and the rest. They get no warning and may break with no notice when the model
implementation changes. The library never calls them on its own models, and a rule test keeps it
that way.

| Instead of                  | Use                                                             |
| --------------------------- | --------------------------------------------------------------- |
| `model_validate(data)`      | `Model.from_json(data)`; the constructor for typed values       |
| `model_validate_json(text)` | `Model.from_json(json.loads(text))`                             |
| `model_dump()`              | `to_json()`; attribute reads for typed values                   |
| `model_dump_json()`         | `json.dumps(model.to_json())`                                   |
| `model_copy(update=...)`    | `replace(**changes)`; a model is immutable, so it needs no copy |
| `model_validate_strings`    | none                                                            |
| `model_fields`              | none                                                            |

- **Not serializable.** `FormFnRegistry` (it holds functions), `ShowLookup` (a cache derived
  from its `Show`) and a `MatchOptions` whose `cost_fn` is set refuse `to_json` and `from_json`
  with `SchemaError` code `NOT_SERIALIZABLE`; the hint says how to rebuild them. Every other
  public model round-trips: `Model.from_json(model.to_json()) == model`, checked by a test for
  each.
- **`ValidationReport.to_json()`** returns the dict (see "Errors and validation").

## Extension keys

<!-- 6eed120d fix(show)!: refuse unknown top-level keys; 26536fac feat(show)!: keep a document's
`x-` keys in `Show.extensions`; 9d4e7400 fix(show)!: drop the export_json extensions keyword;
e23f6825; ed379e38 -->

Hosts can carry their own data through an interchange document under keys that start with `x-`.

- `import_json` stores a document's top-level `x-` keys in `Show.extensions`, a read-only map
  whose keys match `^x-`, empty by default. `export_json` writes them back at the top level, so a
  round trip keeps them.
- Values must be strict JSON, at most `MAX_EXTENSION_BYTES` (1,048,576) bytes of UTF-8 JSON in
  total, checked before they are copied. An `extensions` key inside the show object is refused.
- Any other unknown top-level key is refused with `SchemaError` naming it.
- An empty map is not written, so stored documents of shows without extensions keep their bytes.
  v1 documents migrate to an empty map.
- `export_json` takes no `extensions` keyword; set `Show.extensions` with `replace`.

## Notes document

<!-- a8ca36b2 feat(show)!: move notes out of Show into a notes document; 720ffae2; 5cea7fdb
refactor!: remove the notes package; 2faf98f6; c94d191f; 2314d340 -->

The library keeps no notes: hosts do. It still never loses the notes of a v1 show.

- `Show` has no `notes` field, and a v2 `show.json` has no `notes` key; `Show` refuses one.
- **Stored v1 shows.** The first save after migration writes the show's notes to
  `/notes/notes.json`, in the same revision as the v2 documents, and deletes `/show/notes.json`.
  A v1 tree without notes gets no notes document. Before that save, `migrate_documents` returns
  the document among its outputs.
- **v1 interchange documents.** `migrate_json(d)` returns the notes as its third value; an
  interchange document never carries a `notes` key again.
- **Shape.** Plain JSON: `{"format": "e8.notes", "version": 1, "show": "<show id>", "notes":
[...]}`. Each note keeps its v1 fields (`id`, `text`, `kind`, `anchor`, `author`,
  `created_at`, `visible`). Note IDs follow the ID rename rule for kind `note` (an empty v1 ID
  becomes `id`), anchors point at the renamed sets and spots, and v1 times without a zone are
  read as UTC.
- **Checks.** Workspace writes and commits of `/notes/notes.json` are checked: the document must
  name its own show, note IDs must not repeat ignoring case, a newer `version` raises
  `VersionError` and another `format` `SchemaError` `UNKNOWN_FORMAT`. A write to
  `/show/notes.json` raises `UnknownRefError` naming the new path.
- **After a migration, the host owns the file.** No library function reads or edits it, and
  `renumber`, `remove_set`, `split_section`, `join_sections` and `delete_spots` do not update its
  anchors. A host that keeps notes there applies its own set and spot renames.
- `Anchor` stays public at `e8s.show.models.Anchor`; canvas comments and highlights use it.

## Behaviour changes and fixes

Not breaking signatures, but visible:

- **Every bad geometry input raises an `E8sError`** (`GeometryError`, `SchemaError`,
  `SpacingError`), and public geometry evaluation raises `GeometryError` instead of returning NaN
  or infinity. <!-- 63e92e82; 312d38ce -->
- **SVG path data and font JSON are parsed strictly**; a stray token is named.
  <!-- 6616a727; a87a0862; 5c3ebe22 -->
- **`rename_spots` and `RewriteReport`** are new. `relabel`, `regroup` and `delete_spots` use the
  same rewrite: a facing override aimed at a deleted spot is removed and reported (it was reset
  to `to_target`); a drop that leaves a path row facing a dropped spot is refused with
  `ShowValidationError`; a route left without members is removed and reported.
  <!-- 5a5d4390; c5b3b891; 5b997995; 698e1c61 -->
- **`delete_spots` leaves an open slot** in a non-text form, so later members keep their slots.
  Text forms still close the gap. <!-- 168085a8 -->
- **Matching.** `match_by_order` refuses a repeated spot; non-finite match points are refused;
  `cost_fn` failures are reported; `apply_match` names the spots in a slot collision and reports
  every lock it would break before a match error; `reorder` ranks members and slots to a
  nanometer before breaking ties. <!-- 047133e7; 90dc1c83; 51769a94; a3b22667; 8d40ad13;
  806143ff; 911e9272 -->
- **Fonts work wherever forms are rebuilt.** `match`, `cost_matrix`, `match_by_order`,
  `reorder`, `gate`, `split_form`, `merge_forms`, `morph_targets`, `place`, `rebuild` and
  `apply_match` take keyword-only `font_registry`, so user-font text forms work there.
  <!-- 9a5e381c -->
- **`validate_show` reports** selections naming unknown spots, non-finite values, IDs that
  cannot be stored, mapping keys that differ from their item's ID (`KEY_MISMATCH`) and a show
  longer than `MAX_COUNTS` (`SHOW_TOO_LONG`). <!-- ef708290; 50150970; 027c087a; 82438688 -->
- **Selection.** Ranges round-trip for every ID shape (code `RANGE_PADDING`); selector operators
  evaluate in time linear in the right operand; `parse_selector`, `SelectorAst`, `SelectorToken`
  and `natural_key` are public; `mirror_pairs` pairs by maximum matching within tolerance.
  <!-- 8d4d6468; 8c394d4c; 56725db9; de63d3ca; d8a152d3; 7c0ee8a3 -->
- **Time.** Ramp-end clock math stays in domain (it raised a raw `ValueError` at a ramp end);
  `describe_count` writes large counts without exponents; clock text keeps the sign of negative
  seconds (`-3.8 s` printed `-1:56.2`). <!-- 15883142; 636bbdb0; 96112bca -->
- **Workspace.** `Workspace.show_at` decodes only the documents each revision changed, with a
  bounded cache; models are frozen, so revisions share unchanged objects, and the Phase 2
  scenario asserts one revision's show never changes another's. A renamed set's files read and
  list at their new folder on a v1 head before the first save, and `put_script` on a v1 head
  stores the migration in its own revision first. <!-- 863b58a9; 2eff2dfc; 1240e4f8; 14c591b6 -->
- **Golden outputs match across platforms.** Discrete engine outputs (segment counts, `min_gaps`
  pair orders and top-N lists) differed between x86-64 Linux and arm64 macOS by one-ulp noise:
  on 2026-11-22 the large golden had 4,921 segments on arm64 macOS and 4,922 on x86-64 Linux.
  With one arc-length source in `make_route`, merged near-end breaks in path plans and
  `TrimmedCurve`, and ID-ordered ties, the golden's counts and orders are identical on Linux,
  macOS and Windows, and `nox -s slow` runs on all three in CI. <!-- de9da6ac; e89ac264;
  2358f714; 5e43fbb2; 157c51da; b1123aa8 -->

  before its replacement exists. ADR 0018 (tokenless publication links) is superseded: the code
  it governs is gone.
- **Replacement timing.** ADR 0021's addendum of 2026-11-23 places every replacement in v0.7.0.
  The maintainer moved `frames`, `coordinate_table` and `describe_transition` to v0.5.0 on
  2026-11-23; `locate`, `at_location` and `Location` wait for the markings in v0.7.0.
- **Extras.** ADR 0010 defines five extras; only `tables` and `all` remain. Its question of
  whether PDF sheets need an extra is moot: the PDF writer is removed.
- **Format v2 changed in place.** ADR 0023 gave the dropped stored fields to the v3 step; v2,
  not yet released, drops them instead (ADR 0023 addendum 2026-11-23). Landmark IDs are no longer
  renamed by migration (the ADR 0007 addendum of 2026-11-22 says they are), because landmarks are
  dropped.
- **Not serializable.** ADR 0026 names `FormFnRegistry` and `ShowLookup`; `MatchOptions` with a
  `cost_fn` refuses JSON too, rather than dropping the function without a word.
- **R20: `split_form` and `merge_forms` return custom forms for text input.** A split or merged
  text recipe would re-lay the text and move spots, which a form edit must not do silently.
  Keeping the recipe needs a slot-range field on `TextRecipe`. <!-- lane G R20; 9a5e381c -->
- **R21: `swap` takes no `font_registry`.** It evaluates no layout, so the parameter would be
  unused; a user-font text form already works with `swap`. <!-- lane G R21 -->
- **R11: count and interval spacing on multi-subpath svg forms** keep v0.3.0's layout over the
  summed subpath lengths instead of raising, so v0.3.0 shows keep their slots. <!-- 1b5c6c9a -->
- **D2 R18:** a rewrite that would leave a path row facing a dropped spot is refused, not reset.
  <!-- 5b997995 -->

## Migrating from v0.3

Do these in order. Steps 1 to 4 change your environment; the rest change code and data.

1. **Licence.** Decide whether PolyForm Noncommercial 1.0.0 fits your use. If not, stay on
   v0.3.0 (MIT) or ask the maintainer for a commercial licence.
2. **Python.** Move to Python 3.13 or later.
3. **Package.** Install `e8s` from the `v0.4.0` GitHub release: the attached wheel, or
   `uv add "e8s @ git+https://github.com/abj360/e8s@v0.4.0"`. Change `import showpy` to
   `import e8s` and `from showpy...` to `from e8s...`, `ShowPyError` to `E8sError`, and any
   `SHOWPY_UPDATE_*` variable to `E8S_UPDATE_*`.
4. **Extras.** Add `e8s[tables]` if you call `Set.table`, `paths_table`, `speeds`,
   `energy_curve` or `phrase_profile`. Catch `MissingExtraError` where the extra is optional for
   you. Drop `render`, `qr` and `video` from your requirements.
5. **Removed features.** For each name in "Removed from the library", move the work into your
   app or wait for the replacement named there. Until v0.5.0 there are no frame tables or print
   layouts; until v0.7.0 no coordinate wording, landmarks, zones or stage template.
6. **Keyword-only flags.** Pass every boolean flag by name (see the table). Run mypy or pyright
   to find positional calls.
7. **Errors.** Catch `ShowValidationError` instead of `ValidationError`. Switch on `error.code`
   (an `ErrorCode` member) rather than message text.
8. **Model calls.** Replace pydantic methods with the model interface: `from_json`, `to_json`,
   `replace`. Wrap `ValidationReport.to_json()` in `json.dumps` where you wanted text.
9. **IDs.** Wrap plain strings in the ID `NewType`s where you build models or index model
   mappings (`SpotId("T1")`). `TransitionId` is a `NamedTuple`; unpack it or read `from_set`
   and `to_set`. Do not use `props` as an ID.
10. **Forms.** Build forms with `recipe=` instead of `kind=` and `geometry=`, and read
    `form.recipe`. Treat `None` in `Form.members` as an open slot, or read `Form.spots`. Read
    `SvgRecipe.curves`, not `curve`. Expect `split_form` parts named `<id>_1`, `<id>_2`.
11. **Typed payloads.** Build `MatchWeights`, motion parameter models (`WeaveParams`, ...),
    facing values (`FixedFacing`, `PointFacing`, `EntityFacing`), fix parameters (`DelayFix`,
    ...), `PlacementPatch`, `GroupPatch` and canvas event payload models instead of dicts.
    Decode stored events with `decode_event`. Treat model mappings as read-only.
12. **Selections.** Parenthesize expressions that mix `&` with `+` or `-`. Pass
    `define_selection(..., replace=True)` where you meant to overwrite. Iterate
    `Selection.ids`, not the `Selection`.
13. **Moved names.** Import the form, path and match models from `e8s` or their new modules.
    Call the top-level transforms, or `e8s.choreo.set_*`, for sets; the `e8s.geo` versions take
    points or curves. Use `abs_tol=`, `step=` and `rename_spots`.
14. **Sizes.** Keep casts at 5,000 spots or fewer and shows at 1,000 sets or fewer.
15. **Stored data.** Follow the host checklist below before the first write with v0.4.0.
16. **Interchange.** Prefix host keys in `export_json` documents with `x-`; any other unknown
    top-level key is refused. Read v1 documents with `migrate_json` to keep their report and
    notes. Fix documents holding NaN, duplicate keys or nesting past 100 levels.

### Host checklist: format v2, renames and dropped data

1. **Back up.** Copy each repository before v0.4.0 writes to it. Reading is safe: loading
   migrates in memory and writes nothing.
2. **Do not mix releases.** v0.3.0 and v0.4.0 cannot share a repository. After the first v0.4.0
   save, v0.3.0 refuses the show. To go back, `revert` with v0.4.0 to the last revision v0.3.0
   wrote, or restore the copy.
3. **Get the report.** Before the first save of each show, read its stored documents and call
   `migrate_documents(docs)`; for an interchange document call `migrate_json(d)`. Keep the
   `MigrationReport`: repository loads do not return it in this release.
4. **Apply `MigrationReport.renamed`** to every ID you keep outside the library: performer
   claims and spot assignments, deep links and QR codes, notes and comments, analytics keys, and
   any cache keyed by spot, set, form, route, guide, selection or note ID. Apply it once per
   show, in report order.
5. **Keep what `MigrationReport.dropped` lists** if you still need it: who may claim each spot
   (`claimable`), landmarks, zones and coordinate systems. The values are as stored, with v1
   selector text and pre-rename IDs; map IDs through `renamed`.
6. **Take over the notes.** After the first save, read `/notes/notes.json` (or the third value of
   `migrate_json`) into your app and keep notes there. The library does not update it again.
7. **Expect one hash change.** The first save writes new bytes (header, typed recipes, renamed
   IDs), so `Set.source_hash` and any hash you hold over stored documents mismatch exactly once.
   Stored revision IDs do not change.
8. **Refusals at migration.** A show with a tempo of 0 or less, two tempo sections or two holds
   at one count, a measure length of 0 or less, or an arc of zero sweep raises `SchemaError`
   naming the document, field and value. Fix the stored value with v0.3.0, or report it to the
   designer.
9. **Raw commits.** A host that commits raw documents must write `show.json` with the current
   header; a commit into a tree whose `show.json` has none is refused with `OLD_FORMAT`. Save the
   show once through the library first.
10. **Extension keys.** Keep host data that travels with an interchange document in `x-` keys.

## Known limitations and parked items

- **Speed at the caps.** The caps bound input size, not time. Measured on 2026-11-23 on an
  Apple Silicon machine (10 cores) under a load average of 5 to 10 from parallel runs, so
  absolute times are inflated; minimum of 3 rounds where cheap; sets above 2 are copies of the
  seeded sets with straight moves:

  | Size (spots x sets) | `validate_show` | One-spot save | `compile_all` | Peak memory |
  | ------------------- | --------------- | ------------- | ------------- | ----------- |
  | 300 x 60            | 0.96 s          | 0.10 s        | 0.51 s        | 47 MB       |
  | 300 x 1,000         | 29.6 s          | 5.5 s         | 11.1 s        | 746 MB      |
  | 5,000 x 2           | 2.1 to 2.6 s    | 0.58 s        | 0.4 to 0.5 s  | 68 MB       |
  | 5,000 x 60          | 125.6 s         | 3.9 s         | 12.1 s        | 791 MB      |

  `validate_show` grows superlinearly in sets and spots: 29.6 s at 300 x 1,000 against a linear
  16.7 s, and 130 times the 300 x 60 time at 5,000 x 60 for 16.7 times the placements. A
  one-spot save grows superlinearly in sets: 55 times the time for 16.7 times the sets. The
  budgets are under 1 s for `validate_show` and under 50 ms for a one-spot save at 300 x 60, and
  500 MB peak memory at 300 x 64. A 5,000-spot seeded build takes 7.1 to 11 s. Storage and the
  engine work of later phases own these.

- **Absent capabilities.** No frame tables or print layouts until v0.5.0; no coordinate
  wording, landmarks, zones, stage template or markings until v0.7.0; no rendering, publishing,
  claims or notes in the library at all.
- **Evaluation ledger, still open:** `project()` searches locally, not over the whole curve
  (UP-E-01, deferred to a later release); rectangle footprints in collision checks (UP-E-02);
  scatter components (UP-E-04); matching tie-break (UP-E-05; a fix must give bit-identical
  targets); `arc_through` (UP-E-06).
- **Sheets.** A guide line can survive a resize that puts it off the sheet (UP-9.4-53). Five
  template tests stay open (UP-9.4-30, -32, -34, -36, -37) until v0.7.0 replaces the templates.
- **Text on the field.** Repositories do not store fonts; a reopened user-font show needs the
  caller's registry and fails closed with `MissingFontError`. `split_form` and `merge_forms` drop
  the text recipe (R20). No TTF or OTF fonts, kerning, shaping or text along a curve yet.
- **Reports from repository loads.** `MigrationReport` comes only from `migrate_documents` and
  `migrate_json` until the repository rewrite.
- **Bypassing validation.** pydantic's `model_construct` can build a tempo below `MIN_TEMPO`,
  which then yields infinity in the clock. The library never calls it, and it is not part of the
  model interface.
- **Large modules.** 14 library modules pass 500 lines (not counting `__init__.py` and
  `_api_table.py`), the largest `cast/select.py` (800), `show/models.py` (724) and
  `geo/curves.py` (672).
- **Slow-suite timeout dumps.** `nox -s slow` can print 60 s faulthandler dumps from long tests,
  such as the Phase 1 scenario's `test_two_runs_are_byte_identical`; they are not failures.

## Verification

Run on 2026-11-23 on a clone of `refactor/remove-leaving-names` at `57c8764` (the removal branch
with `main` at `82d9ccd` merged in), macOS arm64, Python 3.14.8.

| Gate                                     | Result                                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| `nox -s tests`                           | 4,002 passed, 7 skipped, `Ledger: 128 open`, coverage 97.48% (branch)        |
| `nox -s slow`                            | 95 passed, 1 xfailed, `Ledger: 1 open` (UP-9.1-72), under hash seeds 0 and 1 |
| `tests/scenario/test_phase2_scenario.py` | passed, in `nox -s slow`                                                     |

The Phase 2 scenario (slow) loads the stored documents v0.3.0 wrote for the seeded 300 spots x
60 sets show, commits them as a v1 tree to a `FileRepository` and migrates through the first
save. It adds a respelled spot, three named selections (two clash by case) and three v1 notes
first. It then saves again, inserts a sub-set and renumbers, retimes ten sets through a second
workspace, replays `events_since` and reverts. It asserts that the report lists every rename and
only those (1 spot, 177 forms, 2 selections, 1 note), that a second save writes no revision,
that selectors pick the same spots throughout, that the notes land in `/notes/notes.json` with
the same text, author and time, that `show.json` opens with `"format": "e8.show"`, continuity
within 1e-6 m and the 0.02 m segment bound, that one revision's show never changes another's,
and that two runs give byte-identical documents, hashes and revision IDs.

The CI matrix (Python 3.13 and 3.14 on Linux, macOS and Windows, plus hash seeds, slow tests on
all three systems, the wheel smoke test, the `core` job without extras, fuzz, bench and Docker)
gates every pull request. v0.4.0 is tagged on `main` only after the full matrix passes on the
merge commit and the maintainer approves the tag.
